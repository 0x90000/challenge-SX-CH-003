## 必须掌握的提交限制

- 首次完整提交仅一次，完整材料送达后不能修改；不能把补身份信息当成替换代码或结果的机会。
- 仅首次被认定为 A，才可在确认邮件发出后 120 小时内提交一次独立完整 S 升级版；升级时 S 仍须开放。
- 默认私密邮箱提交，公开 PR 可选。完整送达时间决定队列，关闭前送达不保证奖金名额。
- 5 个工作日内答复可能只是进入评审、补非实质材料或继续复现，不是承诺认证/付款。
- S 档上限 9,500 元，主办方根据完整度、复现、审计等认定；奖金与税务/身份/权利核验相关。
- 协议第 8 章规定认证/采纳/结算后知识产权与商业使用权的处理；正式提交前须理解并确认具体适用条款。
- 未认证且未采纳/结算的成果，原则上仅允许必要评审、复核、安全审计和合规留存等用途。

## 提交包

先运行 `python scripts/verify.py --coverage --output artifacts/submission-evidence`，
确认 `verification.json` 与测试报告成功，再运行：

```bash
python scripts/package_submission.py --evidence artifacts/submission-evidence
```

输出 `dist/SX-CH-003-submission.zip` 和 SHA256；包括源码、18 策略、样例数据、规范、测试、环境及指定证据。
不包含 `.git`、其他运行目录、虚拟环境、缓存或身份信息。打包不等于向主办方提交。
证据的源码哈希必须与当前代码一致，否则打包拒绝。
