# 验证方法与实际边界

验证日期：2026-10-15。开发验证环境：Windows、Python 3.12.1。
最终可复查结果以提交包 `evidence/verification.json` 及其关联文件为准；开发时在 `artifacts/` 中生成。

## 检查范围

- 单元及集成测试使用 unittest，pytest 只是可选运行器。检查业务不变量、非法输入与真实隔离进程。
- 18 个示例均执行训练、保存、新进程加载、推理、回测，测试要求每个样例实际产生至少一笔成交。
- 同一输入重跑的结果哈希、模型重放、仅修改未来数据不影响过去决策均有断言。
- 现金与库存守恒、手续费/滑点、限价改善、撤单/过期、挂单资金占用、跳空失败、多标的路由均有测试。
- 安全测试涉及禁止导入、文件访问、反射与动态执行、无限循环、C 内建长任务、大内存、工作进程被杀和 Windows 损坏管道清理。
- 故障证据覆盖缺字段、错粒度、错标的、缺模型、非法订单、训练/回测失败、危险导入及兼容启用/禁用。
- 可选 jsonschema 工具检查全部机器 schema、样例声明/行情、真实模型及成功/失败报告。
- Ruff 检查和格式检查用于静态质量；不把格式检查当业务测试。

## 覆盖率解释

`coverage.json` / 控制台表格报告真实父进程行及分支覆盖率，**不设排除来隐藏 worker 未测行**。
工作进程由 `python -I -S` 启动，拒绝继承测试环境，其 main 执行行不计入父进程 coverage，
但由真实子进程黑盒测试覆盖行为。Windows Job Object 的 Win32 建立失败分支、Unix rlimit 在本机的运行情况也不得冒称覆盖。
纯标准库验收不会安装 coverage；只输出测试结果。`--coverage` 收集数值，不影响安全隔离策略。

## 性能测量

固定种子的 100,000 个事件，分开测严格数据验证与带订单/费用/净值的可信引擎。
`benchmark.json` 记录事件数、成交数、耗时、events/s、Python 与平台。
18 策略报告中的 elapsed_seconds 是包含训练、进程启动、IPC 和回测的实际端到端时间。
不要把引擎吞吐误报为包含模型推理的吞吐。性能为单机单次可复现测量，不是跨机器保证。

## 已知限制

- 本机没有 Docker CLI 或可用 WSL 发行版；提供 Dockerfile、强化隔离命令及 Linux/Windows CI，但没有声称它们已在远程执行。
- 仅模拟行情；没有真实交易所连接、生产容量评估或第三方回测引擎实测。
- 全量成交和简化限价模型无队列、部分成交、冲击、企业行动、交易日历、T+1、保证金或多币种。
- 单次输入是有界 JSON，报告保留逐事件证据，所以总存储 O(N)；不是无界行情流平台。
- 受限 Python 不兼容任意 pandas/torch 策略；需通过独立容器后端扩展。
- 训练示例刻意小型化，RL 为单标的库存 MDP，训练奖励是近似执行环境；不能把样例结果解释为论文经济结论。
- 本地验收不是 S 档官方认证，提交前仍须复核档位状态及完整材料。
